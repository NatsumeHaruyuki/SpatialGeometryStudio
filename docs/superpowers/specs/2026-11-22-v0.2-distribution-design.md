# v0.2 桌面分发设计

用户要求：上传完整 v0.2 源码；生成 Windows 11 复制整个文件夹后双击 EXE 即可运行的版本；利用 GitHub Actions 生成 macOS 版本。

用户后续确认 Mac 使用 Apple 芯片，本次 Mac 交付与自动验收目标为 arm64；Intel/Universal 手动构建命令保留，但未验收。

保留当前 v0.2 功能，包版本沿用 package.json 的 0.2.1。源码包含测试、锁文件、示例和构建配置，不提交 node_modules、用户数据或生成的二进制。保留远程初始提交历史。

## 打包方式

- Windows 使用 electron-builder 的 unpacked 目录，包含独立 Electron 运行时，再附带示例、使用说明和版本清单，生成同名 ZIP。复制时必须保留整个文件夹。
- macOS 在原生 Apple 芯片 Actions runner 上构建 arm64，交付含完整 .app 的文件夹 ZIP，保留框架符号链接和执行权限。采用 ad-hoc 签名、关闭 hardened runtime；不冒称 Apple Developer ID 签名或公证。
- 相较原有自解压 portable EXE，unpacked 文件夹直接满足用户的整夹复制要求；相较 Windows 交叉编译 Mac，原生 runner 能实际启动生成的应用。
- macOS 数据放在 .app 同级的 GeometryTeachingData，Windows 放在 EXE 同级；不可写时继续使用既有用户数据回退机制。打包与测试不覆盖任何已有用户项目。

## 验收

运行单元测试和正式构建。Windows ZIP 解压到含中文和空格的另一处目录，在仅系统 PATH、无外部 Electron 条件下启动实际 EXE，再禁用渲染器网络并重新加载，核对渲染、几何操作、Prompt 剪贴板及本地数据路径。macOS 两种架构在 macOS runner 上对解压后的实际 .app 做同类启动检查。Actions 上传 ZIP、SHA256 和验证截图，记录实际运行状态；不以仅写入 workflow 作为已生成 Mac 版本。

实现调整：macos-15-intel 的虚拟 GPU 与 SwiftShader/Vulkan 均无法初始化 WebGL，已由失败日志确认；Rosetta 方案也未完成启动验收。用户明确实际设备为 Apple 芯片后，默认工作流收敛为 arm64 原生构建与启动验证。
